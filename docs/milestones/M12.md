# M12: Fixes: build tool, deconstruction, saves

**Shipped (player-visible):** a new game starts with **40 logs** in the camp stockpile. The **Woodcutter** build bar entry is
greyed out with "Needs 8 logs (have N)" until the logs are there. Drawing a woodcutter's area is followed by a module stage: the
hut, log storage and oxen stand are placed as **ghosts** with a running cost; **Confirm** places the area and every ghost in one
go, and **Cancel** throws the whole draft away. **Expand modules** in the operation panel adds more modules later. Any built module
can be **Deconstructed** (confirm, then it stops working and odd-jobbers take it down over time) for half its logs, and a whole
operation can be deconstructed at once. Cancel deconstruction is offered while it is under way. An operation area with modules
cannot be deleted by right-click ("Deconstruct its buildings first"). In the Load list each save has a bin icon, with a shared
confirm dialog; saves this build cannot read show greyed out with their reason.

**Design sources:** `docs/design/building-tool.md` (BT-01..22), `construction.md` (CN-50..58, CN-53 share), `saving.md`
(SV-23, SV-34), `camp.md` (CMP-06). Technical shape: decisions 0037, 0038, 0039.

## Main technical changes by system

- **Start (`Assets/Sim/Start/`, `Assets/Game/Config/`):** `StartLayout` stock is 40 logs (T-383). `SimConfig` defaults are
  synced to the M12 Sim defaults (T-400), including the deconstruct shares.
- **Build cost (`Assets/Sim/Construction/BuildCost.cs`):** pure queries. `MinimumFor(type)` (8 for woodcutting), `Of(modules)`,
  `CanAfford(world, logs)` against available logs (CN-11) (T-384).
- **Draft preview and batch commands (`Assets/Sim/Operations/DraftModulePlacement.cs`, `Assets/Sim/Commands/`):** a module preview
  checked against the polygon and the other ghosts (T-385). `DesignateOperation` (area + modules, all or nothing, T-386) and
  `PlaceModules` (Expand, T-387). Both reuse `DesignateArea` and `PlaceModule` inside one `Apply`.
- **Deconstruction (`Assets/Sim/Construction/`, `Commands/`, `Tasks/`):** `DeconstructionRegistry` (entries and pending operations),
  `DeconstructionWork` (minutes, refund, finish), `MarkForDeconstruction`, `CancelDeconstruction`, `DeconstructOperation`
  (T-393, T-394, T-395). The `task.deconstruct` def is helpers-only heavy work (T-394). `DeleteArea` refuses an area with modules.
- **Refund tuning:** `DeconstructTimeShare` (0.5) and `DeconstructRefundShare` (0.5) in `SimTuning`, saved in Core.
- **Save (`Assets/Sim/Save/`):** Structures section now holds deconstruction entries and pending operations (validated on read).
  Format version bumped per change (decision 0038); `SaveWriter.CurrentVersion` is 4 (it was 1 at M11).
- **Unity tools (`Assets/Game/Tools/`):** `OperationDraft` (plain state: stages, ghosts, running cost, `CanConfirm`) and
  `OperationDraftTool` (input, palette, ghosts, Confirm sends one command) (T-389, T-390). The Expand path starts the same tool
  in its module stage (T-392). `ModuleTool` was removed.
- **Build bar (`Assets/Game/UI/BuildBar/`):** `ToolEntry.CostLogs` and `BuildEntryState`; the bar re-checks every frame (T-388).
- **Tool panel and confirm (`Assets/Game/UI/ToolPanel/`, `UI/ConfirmDialog/`):** the running cost is in the status line, Confirm
  is gated on `CanConfirm`, and Cancel is wired (T-391). `ConfirmDialog` is a shared UI Toolkit modal on its own UIDocument, used by the operation panel and the Load list
  (T-396).
- **Operation panel (`Assets/Game/UI/OperationPanel/`):** Expand modules (T-392), per-module Deconstruct and state text, and
  Deconstruct operation (T-397).
- **Saves UI (`Assets/Game/Saving/SaveStore.cs`, `UI/GameMenu/LoadPanelController.cs`):** `SaveStore.Delete` (T-398, T-436);
  unreadable saves listed greyed with their reason, Load disabled, bin still working (T-398, T-437, SV-34).
- **Scene:** `GameSceneGenerator` wires the new panels and the confirm host; `Game.unity` regenerated.

## Decisions made

- 0037: an operation and its modules are placed by one command; the draft lives only in the Unity tool.
- 0038: every change to saved bytes bumps the save format version in the same task.
- 0039: deconstruction marks a built module, then a task finishes it; the refund is one unowned pile at the site.
- Owner decisions (in the design docs): CMP-06 40 logs; CN-53 deconstruct takes half the build minutes; CN-56 deconstructing
  the hut unassigns its families; SV-23 delete with confirm; SV-34 greyed old saves.

## Known gaps and debt

- **Placeholder numbers.** The 50% deconstruct time and refund shares are PLACEHOLDER/PROPOSED (CN-53, CN-54), and the build
  recipes are placeholders (CN-02).
- **Build has no walk to the site.** Builders and deconstructors work where they stand (carried over from M10, CN-23).
- **Cost gate only on the woodcutter.** BT-03 (same gate for other buildable entries) waits for the house and granary entries.
- **Unknown-map saves are not greyed.** SV-34 says "older format version, unknown map". Only the version refusal greys a row.
  A save from another map shows as normal and is refused at Load with the SV-30 text.
- **Reader text.** `SaveReader` refuses a bad version with "Unknown save format version N", not the SV-33 wording of decision
  0038. The Load list uses the SV-34 wording instead, so the player sees the friendly text.
- **Deconstruct is only in the operation panel.** The house panel (CN-50, HM-21) is M13.
- **Test evidence.** Sim suite passed (1311, see `docs/test-runs/M12-T-401.md`). Unity EditMode and PlayMode passed in the
  editor, with no counts recorded. The T-402 play check is not written up in `docs/`.
